### 新引导不能直接合并的具体证据

该分支与当前集成分支在本地可得历史中无共同 merge base，且只包含部分项目文件。其 `onboarding-steps.ts`、`onboarding-nav.ts` 和 `App.vue` 仍引用旧 LibraryPage、独立 CreateAssetPage 和旧全局工具入口。当前这些路由已退出主使用流程；头像说明仍写成进入作品，和本次确认不一致。引导还会自动创建“指引体验作品”，需要处理草稿污染和已有作品的保存保护。

建议沿用其吉祥物、聚光组件及账号完成标记，重新映射为：大厅入口 → 账号入口 → 学习/主题任务说明 → 创作图片选择 → 确认图片后后台拆分 → 保存作品 → 可选故事/分享。不能用“下一步介绍完”代替主题解锁的真实完成凭据。自动生成演示草稿、跳过后是否永久标记完成等行为需要产品验收后再启用，本轮保留未接入。

## 二、本轮实际修复

| 问题 | 根因 | 修复 |
| --- | --- | --- |
| 右上角头像直达作品 | `openPersonalCenter()` 调用完成作品入口，页面默认 section 又写死 works | 独立 account/works 入口状态；每次点头像先到账号，显式作品入口和编辑返回仍保留原分类。 |
| 分享区个人标签跳走 | 个人标签复用了个人中心路由，两个标签样式写死 | 恢复分享页内切换和原图激活态；公共页列公开帖，个人页只看当前账号已发布帖，不带出私人草稿。 |
| 问答总给固定素材介绍 | 模型输出解析失败也返回 `ok:true` | 沿用 GitHub JSON 输出参数；非 JSON、字段错误、截断均返回服务失败，保留问题供重试；危险输出明确安全拒绝。 |
| 问答没回应“你是谁” | 提示词只强调拉回素材 | 明确先回应实际问题，自我介绍和意思不清时不能用固定素材介绍替代。模型实际回答质量仍需在线验收。 |
| 气泡文字越过边线、横向滚动 | 正文高度包含气泡尾部；外层滚动条挤占固定宽度；scrollIntoView 可滚动祖先 | 保持原气泡坐标和大小，只收紧文字安全区；为外层滚动条留空间；仅滚动对话容器。 |
| 颜色栏出现“大皮卡丘” | 将所有主体 attributes（包含大小、形状）都当颜色 | 颜色栏过滤非颜色属性，大小仍保留在主体描述；补齐颜色判断，不让“大/圆圆的”视作已选颜色。这是有限的文本识别规则，不是通用语义理解保证。 |
| 点赞/点评返回后串到别的作品 | await 后读取可变化的 `props.post` | 捕获请求时作品 ID，结果只更新对应卡片；切换作品清空上件作品评语。 |
| 分享状态加载失败显示未发布 | 查询失败被 `.catch(() => [])` 吞掉 | 未查到状态显示“分享状态待确认”，不显示发布/撤回按钮，避免将网络失败伪装成未发布。 |

## 四、UI 来源与仍缺的正式交互设计

原画板保持统一等比缩放；未更改 supplied PNG、profile/plaza 美术尺寸或位置。按照前端实现和测试技能，先比对已有素材、再验证实际页面，不把动态 HTML 控件冒称为美术原图。

- **已有美术并继续使用**：大厅场景、账号/作品标签与作品分类、分享双标签、学习书本、身份选择、问答外框/气泡/输入底板/语音按钮、创作录音按钮、展开和 PDF 导出画面。
- **2026-10-13 更正**：此前将问答“发送”和关闭键列为缺素材，核查不充分。`assets/ui/hand-drawn/btn-send.png` 和 `btn-close.png` 已存在，本次恢复使用；创作输入区也已使用 `assets/ui/creation/voice-text.png` 的原始坐标。生成方案的补充/修改/确认/重试仍是复用已有空白手绘按钮底图加动态文字的功能适配，并非美术提供的独立成套成稿。主题任务状态、邮箱/商城侧标签、同步冲突、上传/删除确认等仍须分别核对，不因本页修复而宣称全项目 UI 已还原。
- 这些控件没有删掉必要能力或随意换成另一张语义不同的图。应交付带原画板位置的状态设计，或由团队确认统一的程序控件样式。美术完成与功能完成是两份独立验收。
