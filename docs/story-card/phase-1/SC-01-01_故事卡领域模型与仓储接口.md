# SC-01-01：故事卡领域模型与仓储接口

**状态：** 已定义，待后续任务接入存储实现  
**前置依赖：** SC-00-02 正式故事卡字段契约  
**范围：** 定义已确认故事卡的数据模型与仓储边界；不创建数据库表、不实现仓储类、不实现唯一约束。

## 1. 实现位置

- `src/shared/contracts/story-card.ts`：`StoryCard` 与 `StoryCardRepository`。
- `src/shared/contracts/index.ts`：导出故事卡契约。

## 2. 领域模型

`StoryCard` 仅包含：

- `workId`
- `artworkImageRef`
- `title`
- `storyText`
- `originalAudioRef`
- `confirmedAt`

字段与阶段 0 的正式故事卡契约一致。第一轮转写、候选稿、局部补录音和个人空间数据均不进入该模型。

## 3. 仓储边界

`StoryCardRepository` 定义三个后续实现必须提供的方法：

- `create`：创建一张已确认故事卡；
- `getByWorkId`：按作品 ID 查询故事卡；
- `replace`：覆盖同一作品对应的已确认故事卡。

一作品一卡的唯一约束留给 SC-01-02；具体 Dexie／持久化实现留给后续任务。

## 4. 验证方式

1. 执行 `pnpm exec tsc --noEmit --strict --target ESNext --module ESNext --moduleResolution bundler src/shared/contracts/story-card.ts`，确认新增契约及其依赖可严格编译。
2. 执行 `pnpm exec tsc --noEmit -p tsconfig.node.json`，确认 Node 编译配置可覆盖共享契约。

当前环境没有系统 `npm`，因此 `npm run typecheck` 无法启动；完整网页／测试配置还分别存在既有的 `ImportMeta` 与 `vite/client` 类型配置问题。这些问题不由本任务引入，未在本任务中修改。
