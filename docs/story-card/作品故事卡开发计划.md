# 作品故事卡开发计划

**依据：**《作品故事卡 PRD》V1.0  
**当前策略：** 后端优先；前端仅提供最小测试界面  
**完成定义：** 故事卡的创建、整理、确认、覆盖更新、音频保留和作品图片同步均可通过自动化测试与简单测试界面验证；不以正式 UI 视觉效果作为本阶段验收条件。

---

## 1. 范围与边界

### 本阶段交付

- 故事卡领域数据与持久化接口；
- 语音／手动输入到故事整理稿的服务流程；
- 内容不足、儿童友好措辞与画面引用边界；
- 故事卡确认、覆盖更新、完整重录和局部补录流程；
- 对作品预览图变更的自动同步；
- 用于联调的简单测试界面；
- 单元测试、服务测试和端到端测试证据。

### 本阶段不交付

- 正式儿童化 UI、视觉主题、动效、响应式排版；
- 个人空间、社区发布、权限与审核；
- 图片／PDF 导出与打印；
- 原始转写的展示、保存和版本管理；
- AI 扩写孩子未明确说出的画面情节。

---

## 2. 前置确认项

以下事项不应由故事卡开发自行假定；在进入对应阶段前由项目组确认并记录：

| 项目 | 需要确认的结果 | 影响阶段 |
| --- | --- | --- |
| 语音识别服务 | 可用的普通话／英文／中英混合输入能力、音频格式和返回结构 | 阶段 3 |
| 故事整理服务 | 统一模型调用入口、儿童安全规则和失败降级方式 | 阶段 3 |
| 音频存储 | 完整录音、临时补录音的保存位置及清理策略 | 阶段 2、4 |
| 作品完成事件 | 作品 ID、最新预览图引用和作品修改事件的来源 | 阶段 1、5 |
| 持久化位置 | 本地数据库／应用数据目录的实际表与文件约定 | 阶段 2 |

如果其中任一项尚未可用，先用明确的 Mock 契约完成故事卡内部流程与测试，待统一服务就绪后替换适配层；不在故事卡模块内另建一套 AI 网关或存储体系。

---

## 3. 开发阶段

### 阶段 0：接口与验收基线

**目标：** 把 PRD 转成可验证的输入、输出和测试案例，避免实现过程自行扩展需求。

**工作项：**

1. 将 AC-01 至 AC-15 转为测试用例清单。
2. 定义故事整理请求／响应、内容不足、确认保存、完整重录、局部补录和作品更新的接口契约。
3. 列出领域错误：录音超时、空输入、无法识别、整理失败、故事卡未找到、作品未完成；内容不足作为正常候选稿状态返回。
4. 明确 Mock 的固定返回数据，覆盖中文、英文、中英混合、短文本、不适宜措辞和服务失败。

**完成验证：**

- 契约字段可覆盖正式故事卡的图片、标题、日期、整理稿和最终原始音频；
- 每条验收标准至少有一个正向或异常测试场景；
- 不含个人空间、社区或正式 UI 相关接口。

### 阶段 1：领域模型与作品接入

**目标：** 建立一件作品对应一张故事卡的可靠关系。

**工作项：**

1. 定义 `StoryCard`、输入草稿与处理结果等最小领域模型。
2. 以 `workId` 作为唯一关联键，保证一件作品只有一张正式故事卡。
3. 接入已完成作品的最小上下文：作品 ID、最新预览图、背景／主体／贴纸名称及主题。
4. 建立“作品完成后进入故事卡”和“作品图修改后同步卡片图片”的服务入口。

**完成验证：**

- 对同一 `workId` 重复确认时覆盖原故事卡；
- 作品预览图更新后，关联故事卡图片同步更新；
- 缺失作品或未完成作品不能创建故事卡。

### 阶段 2：录音与输入资产管理

**目标：** 可靠接收完整故事录音、手动输入与局部补录，并区分它们的生命周期。

**工作项：**

1. 实现录音会话状态：未开始、录制、暂停、结束、重录。
2. 限制单次完整录音不超过 5 分钟。
3. 支持在完整录音已存在时手动补充或修改文字；不允许纯文字首次创建正式故事卡。
4. 保存待确认的完整录音；确认后将其设为正式故事卡原始音频。
5. 将局部补录标记为一次性文本修改输入，不替换正式原始音频。
6. 定义未确认录音和局部补录音的清理时机，避免无效文件长期积累。

**完成验证：**

- 暂停、继续、重录和超过 5 分钟均有确定结果；
- 已有关联完整录音的文字补充可进入后续整理流程；
- 局部补录不会改变正式故事卡音频；
- 完整重录确认后才会替换正式故事卡音频。

### 阶段 3：两阶段文本处理服务

**目标：** 将输入安全地整理为可确认的儿童故事，不把中间转写留在正式卡片中。

**工作项：**

1. 第一阶段：调用语音识别，取得仅供本次处理使用的中间转写。
2. 第二阶段：调用故事整理服务，输入中间转写和作品上下文，输出整理稿与建议标题。
3. 处理规则固化为服务约束：删除口语杂音、调整语序、补连接词、保持原语言结构。
4. 对孩子未提到的画面元素，只允许使用不点名的笼统衔接；禁止新增情节。
5. 内容不足时返回 2–3 个补充问题，不自动补写故事。
6. 将不适宜措辞替换为儿童友好的中性表达。
7. 对服务超时、识别失败和整理失败返回统一错误与可重试状态。

**完成验证：**

- 中文、英文和中英混合样例的语言结构不被翻译或强行统一；
- 内容不足样例返回引导问题；
- 画面中未被儿童说出的具体元素不会出现在整理稿；
- 正式 `StoryCard` 不保存第一轮转写；
- 服务失败不产生正式故事卡。

### 阶段 4：确认、保存与内容更新

**目标：** 让候选故事在用户确认后成为唯一正式卡片。

**工作项：**

1. 支持编辑自动标题和整理稿。
2. 仅“确认这就是我的故事”操作可创建或覆盖正式故事卡。
3. 作品修改后自动更新故事卡图片，并返回“保持故事／完整重录／局部补录”选项。
4. 完整重录：替换最终原始音频，重新走识别、整理和确认。
5. 局部补录：以补录内容辅助修改整理稿，保留最终原始音频。
6. 保存确认日期、最终标题、最终整理稿、最新作品图和最终原始音频引用。

**完成验证：**

- 未确认候选稿不可作为正式卡片读取；
- 确认后只存在一张该作品的故事卡；
- 三种作品更新分支均符合 PRD；
- 局部补录和完整重录的音频行为可被自动化测试区分。

### 阶段 5：最小测试界面与端到端联调

**目标：** 以最低前端成本验证真实用户路径与后端接口连通性。

**工作项：**

1. 提供简洁测试页：作品预览输入、完整录音、录制后的文字补充、提交处理、编辑确认、卡片查看和音频播放。
2. 提供内容不足问题展示与补充输入入口。
3. 提供作品修改后的三种更新操作入口。
4. 提供播放／暂停、当前／总时长和可拖动进度条。
5. 以 Mock 跑通完整流程；在服务可用环境下复验一次真实服务流程。

**完成验证：**

- AC-01 至 AC-15 可在测试界面逐项手动复现；
- 测试界面无正式视觉设计验收要求；
- 不引入与后续正式 UI 绑定的复杂样式、组件抽象或页面结构。

### 阶段 6：测试、验收与交接

**目标：** 形成可回归的后端模块，并清晰交接给个人空间与正式 UI 阶段。

**工作项：**

1. 补齐领域模型、录音状态、整理规则、更新分支与错误分支的单元测试。
2. 补齐服务契约测试，验证 Mock 与真实服务适配层返回一致的领域结果。
3. 执行测试界面的关键路径手动验收，记录结果。
4. 编写个人空间接入说明：故事卡读取字段、唯一关系、图片与音频引用、覆盖语义。
5. 编写正式 UI 接入说明：页面状态、可用操作、不可变业务规则和非目标。

**完成验证：**

- 全部自动化测试通过；
- AC-01 至 AC-15 有测试证据；
- 不存在未确认卡片、第一轮转写或局部补录音被错误写入正式故事卡的情况；
- 个人空间和正式 UI 团队无需依赖内部临时转写数据即可接入。

---

## 4. 建议实现顺序与依赖

```text
阶段 0：契约与测试基线
  → 阶段 1：领域模型／作品接入
    → 阶段 2：录音与输入资产
      → 阶段 3：两阶段文本处理
        → 阶段 4：确认与更新
          → 阶段 5：最小测试界面
            → 阶段 6：验收与交接
```

- 阶段 1、2 可以并行准备，但它们的接口必须先由阶段 0 固定。
- 阶段 3 依赖阶段 1 的作品上下文与阶段 2 的输入资产。
- 阶段 5 不应抢在阶段 4 前实现正式流程，只可先做 Mock 联调壳。
- 个人空间与正式 UI 均在阶段 6 后接入，避免在后端数据模型未稳定时返工。

---

## 5. 测试清单

| 类别 | 必测内容 |
| --- | --- |
| 领域规则 | 一作品一卡、确认覆盖、未确认不可读取、图片自动同步。 |
| 录音 | 5 分钟上限、暂停／继续、重录、录制后的文字补充、完整重录、局部补录。 |
| 整理 | 中文、英文、中英混合、口语杂音、内容不足、儿童友好替换、禁止编造。 |
| 数据边界 | 正式卡仅保存最终标题、最终故事、日期、作品图、完整原始音频；不保存原始转写和局部补录。 |
| 错误处理 | 空输入、作品不存在、ASR 失败、整理失败、音频缺失、保存失败。 |
| 联调 | Mock 全链路；真实服务可用时的完整录音与录制后文字补充路径。 |

---

## 6. 阶段完成后的交付物

1. 故事卡领域模型与服务接口说明；
2. 后端实现与自动化测试；
3. 最小测试界面；
4. 验收记录与已知限制；
5. 个人空间接入说明；
6. 正式 UI 接入说明。

---

## 7. 风险与控制

| 风险 | 控制方式 |
| --- | --- |
| ASR／整理服务尚未确定 | 先以稳定 Mock 契约完成模块，服务接入仅替换适配层。 |
| 5 分钟音频处理耗时较长 | 明确处理状态与失败重试，不让未完成结果写入正式卡片。 |
| 整理服务越界扩写 | 使用固定规则、画面信息边界和回归样例测试。 |
| 补录音频与正式音频混淆 | 数据模型中明确区分最终原始音频与临时补录输入，并测试覆盖。 |
| 过早做正式 UI | 测试界面只服务联调，正式视觉与布局单独排期。 |
