# 作品故事卡 PRD

**版本：** V1.0  
**状态：** 需求澄清完成，待视觉设计与开发  
**所属闭环：** 先学习、再创作、后表达  
**适用范围：** 产品、设计、开发、测试

> **当前实施策略：** 本阶段优先完成可独立验证的后端能力与数据闭环。前端仅提供简单测试界面，用于触发、查看和验证故事卡流程；不进行正式视觉设计、儿童化画风、响应式排版或最终页面实现。待后端验收完成后，再开展 UI 设计与前端重构。

---

## 1. 产品定位

作品故事卡是儿童完成背景、主体和贴纸装饰后，对作品进行表达与回顾的功能。它将孩子的口头讲述整理为保留其语言风格的连贯故事，并与完成画面和原始录音共同呈现。

它负责总体产品中的“后表达”环节，不负责主题学习、画布创作、个人空间、社区分享或作品图层拆分。

### 1.1 产品目标

1. 鼓励孩子说明自己的创作想法，而非只完成一张画。
2. 保留孩子原始表达的声音，同时降低口语停顿、跳跃表达带来的阅读门槛。
3. 形成一张可在应用内查看和分享的故事卡，为后续个人空间保存提供内容。

### 1.2 非目标

- 不生成画面中不存在的人物、物品、动作或情节。
- 不替代主题学习、素材解锁、拼贴编辑或个人空间。
- 不导出图片、PDF 或打印物。
- 不保存或展示第一轮语音识别的原始转写文本。

---

## 2. 用户与使用时机

| 用户 | 主要行为 |
| --- | --- |
| 儿童 | 讲述创作想法、补充故事、听自己的录音、确认故事。 |
| 家长／老师 | 协助录音、修改整理稿、确认正式故事卡。 |

### 2.1 进入条件

1. 用户已完成一件包含背景、主体和贴纸装饰的作品。
2. 作品完成后自动保存，并自动进入故事卡板块。
3. 当前阶段只完成故事卡本身；完成后的卡片由后续个人空间模块接收并自动保存。

### 2.2 一件作品对应一张卡

- 每件作品最多一张故事卡。
- 重新确认故事卡时覆盖该作品原有故事卡，不创建版本列表。
- 作品画面发生修改后，故事卡图片自动更新为最新作品画面；系统询问是否更新故事内容。

---

## 3. 故事卡内容与数据边界

### 3.1 正式故事卡必须包含

| 内容 | 规则 |
| --- | --- |
| 作品图片 | 完整背景、主体和贴纸的合成画面；画面比例固定为 902:516。 |
| 作品名称 | 系统根据整理后的故事自动生成；孩子或家长可修改。 |
| 创作日期 | 正式确认故事卡的日期。 |
| 整理后的故事 | 可编辑、可滚动展示的最终文本。 |
| 原始录音 | 保留孩子初次确认时的完整原始录音。 |

### 3.2 中间数据

| 内容 | 用途 | 正式故事卡是否保留／展示 |
| --- | --- | --- |
| 第一轮语音转写 | 为文本整理提供输入 | 否 |
| 补录片段 | 修改整理稿时的辅助输入 | 否 |
| 整理候选稿 | 确认前供编辑 | 仅最终确认稿保留 |

### 3.3 最小接口输入

故事整理服务需要接收：

- 原始录音转写文本；
- 当前作品完整预览图；
- 背景、主体、贴纸的名称及所属主题。

画面与素材信息只用于核对和笼统衔接。孩子未明确说出的元素不得被点名；可使用“画面里的这些小伙伴”等不指向具体元素的表述。

## 4. 页面信息架构

```text
完成作品
  └─ 故事卡引导页
      ├─ 录音与文字补充页
      │   └─ 内容不足引导页（按需）
      └─ 故事确认编辑页
          └─ 正式故事卡详情页

作品修改后
  └─ 更新故事内容确认弹窗
      ├─ 保持当前故事
      ├─ 重新录完整故事
      └─ 补录修改内容
```

### 4.0 当前阶段的测试界面原则

当前页面结构用于验证功能，不构成正式 UI 方案：

- 使用简单、清晰的表单、按钮、文本区域和预览区即可；
- 只需能完成录音、文字补充、提交整理、编辑确认、播放音频和查看故事卡；
- 不实现儿童化插画、视觉主题、动效、最终卡片排版、响应式细节或分享页面；
- 正式“上图下文”卡片视觉布局保留为产品信息架构约束，待后续 UI 设计阶段落地。

### 4.1 故事卡引导页

**目的：** 帮助孩子从“完成画面”自然过渡到“说出故事”。

**信息与操作：**

- 当前完成作品的缩略预览；
- 儿童友好引导语，例如“说说这幅画里发生了什么吧”；
- 开始讲故事；
- 录制完成后补充文字；
- 返回作品。

### 4.2 录音与文字补充页

**目的：** 收集孩子的故事原料。

**信息与操作：**

- 当前作品预览；
- 录音状态：未录制、录制中、暂停、已完成；
- 最长录制时长 5 分钟；
- 开始、暂停、继续、结束、重录；
- 完整录音结束后可补充／修改文字的入口；
- 已完成录音的播放／暂停、当前时长、总时长、可拖动进度条；
- 提交并生成故事。

**规则：**

- 允许暂停与继续录音。
- 重录会替换本次未确认的录音。
- 首次创建故事卡必须先录制完整音频；手动文字仅可在已有本次完整录音后，用于补充或修改故事内容。
- 第一版支持普通话、英文及中英混合输入；整理结果保持原有语言结构。

### 4.3 内容不足引导页

**触发条件：** 转写内容过短、语义不完整，或无法整理成可理解故事。

**信息与操作：**

- 展示 2–3 个简短问题，例如“它们在做什么？”“你最喜欢哪里？”；
- 继续录音补充；
- 改用文字补充；
- 返回重录。

**规则：** 不足内容不由系统自行扩写为完整故事。

### 4.4 故事确认编辑页

**目的：** 让孩子／家长审阅、修改并确认正式故事。

**信息与操作：**

- 自动生成的作品名称，可编辑；
- 整理后的故事文本，可编辑；
- 当前完整原始录音播放器；
- 返回修改输入；
- “确认这就是我的故事”。

**规则：**

- 未点击“确认这就是我的故事”前，不生成正式故事卡。
- 确认后保存最终标题、最终故事文本、确认日期与原始录音。
- 初次创建时，完整原始录音与最终故事绑定。

### 4.5 正式故事卡详情页

**布局：** 上图下文。

- 图片区：完整作品图，固定 902:516 比例，随屏幕等比缩放；
- 信息区：作品名称、创作日期；
- 文字区：最终故事，固定高度、区域内滚动；
- 音频区：播放／暂停、当前时长、总时长、可拖动进度条。

### 4.6 作品修改后的更新确认弹窗

作品修改后，作品图自动同步到故事卡。弹窗提供：

- 保持当前故事内容；
- 重新录完整故事：替换最终音频，并重新整理和确认文字；
- 补录修改内容：保留最终音频，仅用补录内容协助修改原故事文字。

## 5. 核心交互流程

### 5.1 首次创建流程

```text
完成作品
→ 自动进入故事卡引导页
→ 录完整故事，可补充文字
→ 第一次处理：语音识别为中间转写
→ 内容充分？
   ├─ 否：展示引导问题，补充输入后再次处理
   └─ 是：第二次处理：整理为连贯故事
→ 自动生成作品名称
→ 孩子／家长编辑确认
→ 点击“确认这就是我的故事”
→ 生成正式故事卡
→ 交由后续个人空间自动保存
```

### 5.2 文本整理规则

1. 删除停顿词、重复词和不合时宜的语气词。
2. 调整语序，使表达连贯。
3. 可补足明显缺失的主语、指代与连接词。
4. 保持孩子的用语风格及中文、英文、中英混合的原语言结构。
5. 画面信息只能用于笼统衔接，不能新增或点名孩子没有说出的元素。
6. 不得编造画面外人物、物品、动作或情节。
7. 不适宜表达替换为儿童友好的中性表达后再生成故事。

### 5.3 作品修改后的更新流程

```text
用户修改已有关联故事卡的作品
→ 故事卡图片自动更新
→ 询问是否更新故事内容
  ├─ 否：保留最终故事文本与原始音频
  ├─ 重新录完整故事：覆盖原始音频，重新整理、编辑、确认
  └─ 补录修改内容：保留原始音频，依据补录修改最终故事文本，再确认
```

---

## 6. 业务规则

1. 仅完成作品后可进入故事卡流程。
2. 原始录音最长 5 分钟。
3. 故事卡文本只展示最终整理稿，不展示或保存第一轮原始转写。
4. 一件作品只保留一张故事卡；确认保存时覆盖原卡。
5. 作品图修改后必须自动同步到故事卡。
6. 局部补录不得替换故事卡的最终原始音频。
7. 只有重新录制完整故事时，才能替换故事卡的最终原始音频。
8. 正式故事卡仅用于应用内查看和分享，不提供图片／PDF 导出与打印。
9. 当前模块只定义故事卡产物；个人空间保存、社区分享、权限与审核由对应模块实现。

## 7. 版本范围

### 7.1 第一版包含

- 故事卡后端数据模型、处理流程与可测试接口；
- 完成作品后自动进入故事卡；
- 最长 5 分钟的录音、暂停、重录与录制后的文字补充；
- 普通话、英文、中英混合的输入整理；
- 两阶段处理：语音识别中间转写、故事整理；
- 内容不足时的补充问题引导；
- 自动标题、编辑整理稿和明确确认；
- 上图下文的故事卡详情；
- 音频播放、时长显示和进度拖动；
- 作品修改后的图片同步与内容更新流程。

### 7.1.1 当前开发阶段的前端范围

- 提供用于联调的简单测试界面；
- 测试界面能够构造作品输入、录制或输入故事、查看整理结果、编辑确认并播放音频；
- 测试界面不作为正式交付页面，不冻结其视觉与交互细节。

### 7.2 第一版不包含

- 个人空间页面、社区分享页面与权限；
- 图片／PDF 导出或打印；
- 原始转写展示、保存与版本历史；
- 多张故事卡、多版本对比；
- AI 主动创作未被儿童说出的画面情节；
- 方言识别质量保证。
- 正式 UI 画风、视觉规范、儿童化动效、完整卡片排版和响应式页面设计。

## 8. 验收标准

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| AC-01 | 完成作品 | 系统自动进入故事卡引导页。 |
| AC-02 | 录音 | 可录制最多 5 分钟，支持暂停、继续、重录。 |
| AC-03 | 文字补充 | 完成完整录音后可补充文字并生成故事；不得以纯文字首次创建正式故事卡。 |
| AC-04 | 内容不足 | 不自行补写完整故事，显示 2–3 个补充问题。 |
| AC-05 | 文本整理 | 删除口语杂音、调整语序，保留原语言结构与孩子口吻。 |
| AC-06 | 画面引用 | 孩子未提及的元素不被点名、不被赋予新情节。 |
| AC-07 | 内容安全 | 不适宜词替换为儿童友好中性表达。 |
| AC-08 | 确认 | 整理稿和标题均可编辑；未点击确认不得生成正式卡。 |
| AC-09 | 正式卡 | 显示图片、名称、日期、最终故事和原始录音；不显示原始转写。 |
| AC-10 | 长文本 | 文字区固定高度，超出内容在区内滚动。 |
| AC-11 | 音频 | 支持播放／暂停、当前／总时长和可拖动进度。 |
| AC-12 | 作品更新 | 作品图自动同步；可保持故事、完整重录或局部补录修改文字。 |
| AC-13 | 局部补录 | 最终播放音频保持原完整录音，仅故事文字更新。 |
| AC-14 | 完整重录 | 最终播放音频被新完整录音替换，故事需重新确认。 |
| AC-15 | 测试界面 | 可通过简单测试界面完成输入、处理、确认、查看和播放的全流程；不以视觉设计为验收项。 |

---

## 9. 与总体 PRD 的衔接

本 PRD 细化总体 PRD中的“作品故事卡”模块：引导教育模式下，作品完成后默认进入故事卡；自由创作模式是否进入故事卡由产品流程决定。故事卡完成后应自动进入个人空间，但个人空间与分享社区的页面、存储、权限和审核不在本 PRD内实现。
