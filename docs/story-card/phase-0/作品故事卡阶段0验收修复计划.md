## 2. 必须修复

### RF-01：纯手动输入与原始音频字段冲突

**问题：** 输入契约允许 `manual_text` 不提供音频，而正式 `StoryCard` 要求 `originalAudioRef` 必填，因此纯手动输入无法生成合法正式故事卡。

**人工确认节点：** 在修改前，项目组必须从以下规则中选择一个，不能由开发自行决定：

| 选项 | 规则 | 影响 |
| --- | --- | --- |
| A | 手动输入仅用于补充或编辑，首次创建正式故事卡必须有完整录音。 | 保持 `originalAudioRef` 必填；收紧手动输入流程。 |
| B | 允许无录音的纯文字故事卡。 | `originalAudioRef` 改为条件字段；详情页需处理“无音频”状态。 |
| C | 手动输入仅作为录音识别失败后的替代文本，但仍保留本次已录制完整音频。 | 保持音频必填；手动输入请求需带已有完整录音上下文。 |
| D | 取消纯手动输入入口。 | 保持音频必填；修改 PRD、计划、任务拆分和输入契约。 |

**推荐：** A。它最符合“故事卡保留孩子原始声音”的既定产品目标，且修改范围最小。

**影响范围：**

- `SC-00-02_作品故事卡字段契约.md`；
- `SC-00-04_作品故事卡输入请求契约.md`；
- `作品故事卡PRD.md` 中手动输入规则；
- `作品故事卡开发计划.md`、`作品故事卡开发任务拆分.md` 中相关描述；
- 验收用例 `TC-03`、`TC-09` 及对应 Mock 数据。

**完成检查：**

1. 每一种允许的输入路径都能构造合法正式 `StoryCard`；
2. 不允许的路径在契约和验收用例中被明确拒绝；
3. `originalAudioRef` 的必填／条件规则在全部文档中一致；
4. 仅修改与该冲突直接相关的文档和 Mock。

### RF-02：“内容不足”的错误语义不一致

**问题：** 任务拆分要求统一错误码覆盖“内容不足”，但候选稿契约将其设计为正常的 `needs_more_input` 状态，统一错误契约中没有对应错误码。

**修复策略：** 将“内容不足”明确为正常可继续的候选稿状态，而不是错误；任务拆分和错误契约说明必须与该规则一致。

**影响范围：**

- `作品故事卡开发任务拆分.md` 的 SC-00-06 完成标准；
- `SC-00-03_作品故事卡候选稿契约.md`；
- `SC-00-06_统一错误契约.md`；
- `作品故事卡验收用例与验证记录.md` 中 TC-04 与 SC-00-06 记录。

**完成检查：**

1. 文档明确 `needs_more_input` 是正常结果，不是 `failed`；
2. `StoryCardErrorCode` 不再被要求包含“内容不足”；
3. TC-04 继续验证补充问题，不验证错误码；
4. 不新增与内容不足重复的错误类型。

### RF-03：缺少服务失败 Mock 样例

**问题：** SC-00-07 要求 Mock 覆盖服务失败，但现有数据集没有 `failed` 样例。

**修复策略：** 新增一个最小失败样例，优先覆盖 `STORY_REWRITE_FAILED`；若后续 ASR Mock 已具备音频输入，再单独增加 `TRANSCRIPTION_FAILED`，不在本次一并扩展。

**影响范围：**

- `测试数据/SC-00-07_故事处理Mock数据集.json`；
- `测试数据/README.md`；
- `作品故事卡验收用例与验证记录.md` 中 SC-00-07 记录。

**完成检查：**

1. JSON 保持可解析；
2. 新样例的预期状态为 `failed`；
3. 新样例引用统一错误契约中的现有错误码、用户安全提示和 `retryable`；
4. 现有五条成功／内容不足样例不改动。
