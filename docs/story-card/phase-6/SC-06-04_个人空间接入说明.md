# SC-06-04 个人空间接入说明

**任务状态：** 已完成并通过人工审阅  
**接入对象：** 个人空间中的已确认作品故事卡展示。  
**范围：** 说明正式故事卡的读取与展示边界；不实现个人空间页面、分享、编辑或新的接口。

## 读取入口与空状态

个人空间应按作品的 `workId` 读取正式故事卡：

```ts
const card = await getStoryCardDetail(workId, repository)
```

- `workId` 为空时，读取会返回 `INVALID_ARGUMENT`。
- 该作品尚未确认故事卡时，读取会返回 `STORY_CARD_NOT_FOUND`；个人空间应展示“尚未创建故事卡”的空状态，而不是自行构造候选故事。
- 只读取已确认的 `StoryCard`，不读取或缓存临时候选稿。

## 允许读取和展示的字段

| 字段 | 含义 | 个人空间使用规则 |
| --- | --- | --- |
| `workId` | 已完成作品的唯一标识 | 用作作品与故事卡的关联键，不作为儿童可见文案。 |
| `artworkImageRef` | 作品当前预览图引用 | 直接作为作品图片资源引用展示。 |
| `title` | 已确认的故事标题 | 直接展示。 |
| `storyText` | 已确认的最终故事正文 | 直接展示，可在个人空间按页面需要分页或滚动。 |
| `originalAudioRef` | 已确认的完整原始录音引用 | 仅用于播放完整原始录音；按资源协议读取，不替换为补录音。 |
| `confirmedAt` | 最后一次正式确认时间（UTC ISO 8601） | 在界面按当地时区格式化后展示。 |

## 唯一关系与覆盖语义

- 一个 `workId` 最多对应一张正式故事卡；存储以 `workId` 为主键。
- 首次确认创建该卡；同一作品再次确认时覆盖原卡，不新增第二张记录。
- 个人空间列表或详情不得按确认次数堆叠多张故事卡；重新进入时应按 `workId` 重新读取最新卡片。
- 作品预览图更新时，系统只同步 `artworkImageRef`，保留 `title`、`storyText`、`originalAudioRef` 和 `confirmedAt`。
- 局部补录后确认可更新故事文字，但原 `originalAudioRef` 必须保持不变；完整重录确认后才允许替换它。

## 图片与音频引用规则

- `artworkImageRef` 是当前作品预览的资源引用。个人空间不复制图片，也不从故事正文或候选稿推导图片。
- `originalAudioRef` 必须是确认后的完整录音引用；个人空间不接受 `temp/` 临时录音引用，也不接受 `partial_supplement` 局部补录音。
- 音频播放控件可由个人空间自行设计，但只能播放 `originalAudioRef`；不得把播放进度、转写或服务商响应写回故事卡。

## 禁止依赖的数据

以下数据不属于正式 `StoryCard`，个人空间不得读取、展示或持久化：

- 第一轮语音转写；
- `StoryCardDraft` 的候选标题、候选正文、补充问题和失败信息；
- 临时完整录音、局部补录音及临时资源路径；
- 故事整理服务的原始响应、密钥或诊断信息；
- 作品画布内部图层、坐标和素材 ID。

## 验证方式

```powershell
npx.cmd vitest run tests/story-card/story-card-detail.service.test.ts tests/story-card/story-card-artwork-sync.service.test.ts tests/persistence/story-card-store.test.ts
npm.cmd run typecheck
```

通过标准：详情读取只返回表中的六个正式字段；同一 `workId` 覆盖后仍只有一张正式卡；图片同步不改变正文和原始音频。
